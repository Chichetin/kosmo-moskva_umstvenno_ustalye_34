# План: мониторинг СМИ и проверка сообщений о паводках — MVP

**Статус (26.09.2026): этапы 2–5, 7, 8 и форма очевидцев (#156) реализованы автономным модулем
`floodvalue.media` без подключения к глобусу (#168, D-051); этап 6 (слой на глобусе) ждёт
`area:app`; этап 1 — частично (проверены GDACS и GDELT, GDELT живьём не ответил); этап 9 не
начат. Запуск и границы — `docs/features/media-monitoring-run.md`.** Исходный статус плана:
запланировано, не начато. Спецификация — `docs/features/media-monitoring.md`,
issue сквозного MVP — #156 (он шире: форма очевидцев там — отдельный этап после проверки
условий, здесь — развитие). Работа начинается **после сдачи кейса** (стоп-код 27.09.2026
01:00 МСК, D-033). До сдачи эти этапы не берутся: они не дают баллов ни по одному из 20
критериев и не должны отвлекать от комплекта.

Все сроки и целевые значения ниже — **предварительные оценки для обсуждения**. Ни одна
метрика не достигнута и не измерялась.

## Границы MVP

| | MVP | Последующее развитие |
|---|---|---|
| Источники | 1 новостной (RSS выбранного издания или GDELT) + 1 сводка (например GDACS) — после проверки условий | Больше изданий и языков, ReliefWeb, форма очевидцев (#156, раздел К спецификации) |
| География | Один регион и один-два языка (выбор — этап 1) | Расширение по регионам. Полный мировой мониторинг не обещается |
| Наблюдения | Поиск по **локальному** каталогу `source_manifest_s1.json`. Анализ — существующей командой вручную | Внешний каталог (например Copernicus Data Space), автоматическая загрузка и обработка новых сцен |
| Действия с планом съёмки | «Отправить на проверку» записывает `follow_up=needs_imagery` | Предложение кандидатной зоны в `procure` — отдельным PR контракта |
| Хранилище | SQLite вне git (предложение) | Серверная БД |
| Интерфейс | Слой «Сообщения» и карточка на глобусе, который окажется в `main` | Уведомления, подписки на территории объектов |

## Этапы

### 1. Проверка источников и требований

- [ ] Выбрать регион, языки, 1 новостной источник и 1 сводку.
- [ ] По официальной документации каждого кандидата записать: доступность, формат,
      условия использования, атрибуцию, ключи, лимиты, стоимость, можно ли хранить
      контент. Непроверенное помечать «требует проверки».
- [ ] То же для геокодера и доступа к языковой модели (провайдер, стоимость, лимиты).
- [ ] Решить, где работает фоновый процесс после хакатона.

**Результат:** таблица источников с проверенными условиями и ссылками на документацию.
Решение `D-…` о составе MVP.
**Зависимости:** нет.
**Приёмка:** у каждого выбранного источника условия подтверждены ссылкой на официальный
документ с датой проверки. Источник без подтверждённых условий в MVP не входит.
**Не входит:** код, ключи, подписки, оплата.

### 2. Минимальная инфраструктура и хранение

- [ ] Модуль `src/floodvalue/media/` по правилам импортов проекта. Запуск
      `python -m floodvalue.media`.
- [ ] Схемы сущностей (раздел Г спецификации) — pydantic.
- [ ] Хранилище (SQLite вне git), путь из переменной окружения.
- [ ] Планировщик с настраиваемым `poll_interval` (начальное допущение — 15 минут).
- [ ] Тест-«файрвол»: `model`, `calibration`, `assets`, `procurement`, `export` не
      импортируют и не читают `media`.
- [ ] Новые зависимости — отдельным PR в `uv.lock` с `reviewer`.

**Результат:** пустой конвейер запускается по расписанию и пишет `source_run`.
**Зависимости:** этап 1 (где работает процесс).
**Приёмка:** холостой запуск пишет запись запуска. `make all` и `make validate` дают тот
же результат, что до изменений: 12/12, хеши `flood_probability.tif` и `flood_mask.tif` и
порог на демо-чипе совпадают. `make check` зелёный.
**Не входит:** реальные источники, модель, интерфейс.

### 3. Сбор публикаций и защита от повторной обработки

- [ ] Адаптеры выбранных источников. Нормализация в `publication`.
- [ ] Дедуп по каноническому URL и `content_hash`.
- [ ] Повторы с паузой, таймауты, ограничение частоты. Статус последней успешной проверки.
- [ ] Хранение по `content_storage_policy` источника.

**Результат:** публикации копятся в хранилище без дублей.
**Зависимости:** этапы 1, 2.
**Приёмка:** повторный запуск на тех же данных не создаёт новых записей. Недоступный
источник даёт `status=failed` и не роняет остальные. Тесты на сохранённых ответах
(фикстуры), без сети.
**Не входит:** классификация, извлечение, события.

### 4. Извлечение события и уточнение географии

- [ ] Предварительный фильтр кода (язык, ключевые слова).
- [ ] Вызов модели со строгой схемой: релевантность, `report_type`, топонимы-строки, время
      события и его точность, суть. Валидация. Невалидное → `needs_review`.
- [ ] Геокодирование, `geo_precision`, `geo_status`. Неоднозначное → `needs_geo`.
      Отсутствующее → пусто, не [0, 0].
- [ ] Лимит вызовов и оценка затрат.
- [ ] Тест на внедрение инструкций: текст статьи с «инструкцией» не меняет поведение.

**Результат:** у релевантных публикаций есть проверенные извлечённые сведения.
**Зависимости:** этап 3.
**Приёмка:** проверочные примеры 1–5 и 7 (ниже) дают ожидаемые тип и статус геопривязки.
Модель не возвращает координат, которые попали бы в хранилище.
**Не входит:** объединение, интерфейс.

### 5. Объединение публикаций

- [ ] Правила уровней 1–4 из раздела Е спецификации.
- [ ] Первоисточник и перепечатки, `independent_origin_count`.
- [ ] Ручное объединение и разделение с записью в `history`.

**Результат:** реестр событий.
**Зависимости:** этап 4.
**Приёмка:** примеры 6 и 10 проходят. Ручное разделение переживает повторный
автоматический пересчёт.
**Не входит:** интерфейс.

### 6. API и слой сообщений на глобусе

- [ ] Эндпоинты чтения событий с фильтрами и действия аналитика.
- [ ] Слой «Сообщения», карточка события, фильтры, четыре действия (раздел Ж).
- [ ] Безопасное отображение текста.

**Результат:** аналитик видит события на глобусе.
**Зависимости:** этап 5; **интерфейс с глобусом в `main`** — сейчас его нет (PR #120
черновой, D-034 — Streamlit). Если глобуса в `main` нет, этап блокирован.
**Приёмка:** слой выключается и не закрывает растры. Область показывается областью, а не
точкой. Мигающих маркеров нет. Демо и replay подписаны.
**Не входит:** новый отдельный dashboard.

### 7. Проверка оператором

- [ ] Сохранение `review` с четырьмя результатами и основанием.
- [ ] Переходы `review_state`, журнал.
- [ ] «Отправить на проверку» → `follow_up=needs_imagery`, без записи в
      `candidate_orders.geojson`.

**Результат:** у события есть проверяемая история решений.
**Зависимости:** этап 6.
**Приёмка:** без подходящего наблюдения нельзя выставить `consistent` или `discrepancy`
(доступно только `insufficient_data` или `not_checked`). Файлы комплекта `outputs/` не
меняются.
**Не входит:** автоматическая закупка, изменение A/B/C.

### 8. Поиск подходящих спутниковых наблюдений

- [ ] Поиск по локальному каталогу (`source_manifest_s1.json` и комплекты `outputs/`) по
      пересечению территории и окну времени.
- [ ] `observation_match` с `suitability` и причиной.
- [ ] Переход к существующему анализу (`predict` / `make all`) — ручной, по кнопке или
      команде.

**Результат:** для события видны кандидаты-наблюдения с объяснением.
**Зависимости:** этап 6. Test запечатан: поиск не читает метки, test-чипы не
используются до `eval-test`.
**Приёмка:** пример 9 даёт `too_early` / `too_late`, а не «подтверждено». Отсутствие
сцены даёт `insufficient_data`.
**Не входит:** внешний каталог, скачивание и автоматическая обработка новых сцен — это
отдельный этап развития.

### 9. Тестирование качества и демонстрация

- [ ] Размеченный вручную набор публикаций для оценки (вне git, если тексты чужие).
- [ ] Измерить критерии качества (ниже) и записать в `docs/verification/` с командой.
- [ ] Replay-сценарий с `is_replay` / `is_demo` на validation-чипе.

**Результат:** отчёт о качестве с измеренными числами и демонстрация.
**Зависимости:** этапы 1–8.
**Приёмка:** каждое число в отчёте получено командой из отчёта. Replay не попадает в
метрики модели. `make all` и `make validate` — без изменений.
**Не входит:** обещания точности на других регионах и языках.

## Проверочные примеры

Тексты — вымышленные (`is_demo=true`), кроме случаев, когда источник разрешает хранение.

| # | Случай | Ожидаемое поведение |
|---|---|---|
| 1 | Реальное (по смыслу текста) сообщение о подтоплении: «подтоплены дворы в посёлке X сегодня утром» | `report_type=occurred`, событие создано, точность — населённый пункт |
| 2 | Прогноз: «в ближайшие дни возможен подъём воды» | `forecast`, на глобусе не выглядит произошедшим затоплением |
| 3 | Отрицание: «информация о подтоплении не подтвердилась» | `negation`, привязано к событию, событие не удалено, результат проверки не изменён |
| 4 | Старая новость: обзор паводка десятилетней давности | `historical`, по умолчанию скрыто |
| 5 | Неоднозначное место: название, у которого несколько населённых пунктов | `geo_status=ambiguous`, `needs_geo`, варианты для аналитика, без выбора наугад |
| 6 | Несколько перепечаток одной заметки | Одно событие, `independent_origin_count=1` |
| 7 | Отсутствие координат: «в регионе сильные паводки» без топонима ниже региона | Точность «регион» или `missing`. Не точка, не [0, 0] |
| 8 | Недоступный источник (таймаут, 5xx) | `source_run.status=failed`, остальные источники работают, в интерфейсе видно время последнего успеха |
| 9 | Неподходящий по времени снимок: сцена на 2 недели раньше события | `suitability=too_early`, результат — `insufficient_data` или `not_checked` |
| 10 | Быстрое повторное обновление одного события: публикация обновлена через 10 минут | Та же публикация и то же событие, запись в `history`, без дубля |

Дополнительно: статья со встроенной «инструкцией для ИИ» не меняет извлечение и не
вызывает действий.

## Критерии качества

Определения фиксируются на этапе 1. Целевые значения — **предварительные, для обсуждения**,
не достигнутые.

| Критерий | Как измерять | Предварительный ориентир |
|---|---|---|
| Релевантность | precision / recall отбора «про паводок» на размеченном наборе | определить после разметки |
| Точность места | доля событий с верным уровнем точности; расстояние до эталона для `point` / `locality` | определить после разметки |
| Точность времени | доля событий, у которых интервал содержит эталонное время | определить после разметки |
| Качество объединения повторов | доли ошибочных слияний и пропущенных слияний на размеченных парах | ошибочное слияние хуже пропущенного: при сомнении — не сливать |
| Доля ручной проверки | доля публикаций в `needs_review` / `needs_geo` | измерять. Слишком высокая — сигнал пересмотреть фильтр |
| Задержка | медиана и 90-й перцентиль `fetched_at − published_at` и `first_detected_at − published_at` | зависит от интервала опроса (допущение — 15 мин) и источника |
| Стоимость | вызовы модели и оценка затрат на 100 публикаций и на сутки | лимит задаётся на этапе 1 |
