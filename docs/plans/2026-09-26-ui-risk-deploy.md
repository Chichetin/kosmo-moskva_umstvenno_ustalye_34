# Интерфейс рисков: состав изменения и передача на деплой

Ветка: `worktree-ui-risk-scenarios`. База: `0bb57fc` (PR #267).
Перед передачей объединена с `origin/main` на `68feb45`; сохранены обновления
масштаба, навигации, списка наблюдений и новостей. Бандл пересобран после объединения.

## Что доставляется

- Интерактивная диаграмма: X = вероятность воды, Y = условные потери V·q.
  Цвет отражает энтропию в битах, если такой показатель указан в комплекте;
  иначе нейтральный. Выбор связан с таблицей и существующей кнопкой карты.
- Заметная группа объектов без оценки (`partial`, `no_data`, невалидные входы).
  В числах показываются прочерки; если оценённых объектов нет, сумма тоже неизвестна.
- Очередность, действие и причина из уже существующего
  `run_metadata.expected_loss.inspection_priority` (D-035). Нового алгоритма осмотра нет.
  Старые комплекты без этого поля показывают сообщение об отсутствии рекомендаций.
- A/B/C: полная стоимость, соответствие бюджету данных, остаточная неопределённость,
  её статус и основание. Для энтропии единицы суммы — биты, без ошибочного диапазона 0–1.
- Срок решения, время доступности зон с UTC, учебные V/q и сценарность цен/сроков.
  Пояснение предположений R (симметричная цена ошибок, идеальное уточнение).
- Сохранены существующие оформление, карта зон плана C, чувствительность и экспорт.
  На телефоне диаграмма дополнена кнопками объектов; шапка анализа укладывается в 320 px.

**Монте-Карло в этой версии нет.** После замечания пользователя о совместном затоплении
отдельный сценарный блок исключён из изменения. Формула EL, модель p, калибровка,
оптимизатор и научные артефакты не меняются. Минимум/максимум ансамбля не трактуется
как вероятностный закон; новых оценок хвостов ущерба или предотвращённых потерь нет.

Изменены только `web/`, собранный `src/floodvalue/app/static/` и этот документ.
Python API, зависимости, конфиги, данные и веса не меняются. Пересчитывать результаты
или открывать test для обновления интерфейса не требуется.

## Действия следующего агента

1. Доставить коммит ветки `worktree-ui-risk-scenarios` в серверный checkout по процедуре
   `deploy/README.md`. Проверить текущую ветку и чистоту дерева. Если сервер основан на
   базе этой ветки, допустим `git fetch origin worktree-ui-risk-scenarios` и
   `git merge --ff-only FETCH_HEAD`. При расхождении сначала объединить изменения
   обычным рабочим процессом; не сбрасывать чужие изменения.
2. Собранные JS/CSS и `index.html` включены в коммит. Node на сервере не требуется.
   Если сборка выполняется заново: `cd web && npm ci && npm run build`.
   Доставлять `index.html` и каталог `assets/` вместе; старые имена бандлов заменены.
3. Перезапустить сервис сайта согласно способу установки:
   `systemctl --user restart floodvalue-site` либо системный `floodvalue-site`.
   Схема БД, переменные окружения и воркер СМИ не требуют изменений.
4. Открыть готовую сцену → «Анализ». Проверить диаграмму, объект без оценки (если есть),
   A/B/C и смену бюджета. Проверить переход к карте и выгрузку комплекта.
5. Проверить наличие `expected_loss.inspection_priority` в серверном комплекте.
   Если поля нет, интерфейс честно покажет отсутствие рекомендаций. Для получения
   рекомендаций нужен комплект, экспортированный существующими этапами `assets`/`export`
   текущей версии, а не повторное обучение. Не править JSON вручную.

Деплой в рамках этой задачи не выполнялся.
