# Мониторинг сообщений о паводках и форма очевидцев — запуск (#168)

Отдельный модуль `src/floodvalue/media/`, часть #156. **К интерфейсу оператора (глобус,
`area:app`) пока не подключён** — это отдельная задача после освобождения `area:app`. До
подключения у модуля своя страница аналитика `/media/analyst`. Спецификация —
`docs/features/media-monitoring.md`, план — `docs/plans/media-monitoring-mvp.md`, проверка —
`docs/verification/media-smoke-2026-09-26.md`.

Модуль не меняет и не читает p, маску, порог, метрики, портфель, EL и A/B/C. Ни один этап
FloodValue его не импортирует (`tests/media/test_media_firewall.py`). `make all` и
`make validate` его не запускают.

## Что реализовано

| Часть | Состояние |
|---|---|
| Хранилище SQLite вне git: источники, публикации, обращения, события, связи-свидетельства, наблюдения, проверки, журнал запусков, история | есть; данные переживают перезапуск |
| Сводки GDACS (`gdacs_floods`, тип «сводка») | подключено, **проверено живьём** 26.09.2026 |
| Новости GDELT DOC 2.0 (`gdelt_floods`, тип «СМИ», только заголовок и ссылка) | адаптер есть. **Живьём не проверен**: API отвечал 429 на наш IP весь день 26.09 (см. отчёт) |
| RSS-лента издания | адаптер есть, в `sources.yaml` выключен: у каждой ленты свои условия, их надо проверить |
| Извлечение | правила `rules_v1`: произошло / прогноз / предупреждение / отрицание / исторический / неясно, неоднозначное — на ручную проверку. Адаптер языковой модели — интерфейс и строгая схема **без провайдера**: платный сервис не подключался |
| География | точность (точка … страна, неизвестно), неоднозначность → варианты для аналитика, отсутствие → пусто (не [0, 0]). Геокодер Nominatim **выключен по умолчанию** (`FLOODVALUE_MEDIA_GEOCODER=nominatim`) |
| Объединение | та же публикация (id, URL, хеш), перепечатка (URL / заголовок) — `is_original=0`, та же ситуация (место ≤ 25 км, время ± 3 сут, тот же тип). Ручные объединение, разделение, исправление места и времени с историей |
| Форма очевидца `/report` | отдельная страница под телефон, фото (до 3, без EXIF), статус по личной ссылке, защита от дублей, черновик сохраняется при обрыве сети |
| Модерация | очередь новых обращений, принять → новое событие / привязать к выбранному, отклонить, спам |
| Поиск наблюдений | локальный каталог Sen1Floods11 (без test-событий, только границы растров) и каталог Copernicus Data Space (поиск записей, **проверено живьём**). Подготовка и анализ новых сцен **не реализованы** — показываются как «найден в каталоге» |
| Серверный сбор | `worker` с файловой блокировкой, интервал из `sources.yaml` (15 мин — стартовая настройка, не обещание задержки), включение/выключение, ручной запуск, бюджеты запросов, остановка по SIGTERM без потери данных |

## Запуск

```bash
uv sync --frozen
uv run python -m floodvalue.media init          # база $FLOODVALUE_MEDIA_DIR/media.sqlite
uv run python -m floodvalue.media demo          # ДЕМО-сообщения (replay, Sri-Lanka 2017, validation)
uv run python -m floodvalue.media ingest        # ручной сбор всех включённых источников
uv run python -m floodvalue.media ingest --source gdacs_floods
uv run python -m floodvalue.media sources       # состояние источников
uv run python -m floodvalue.media serve         # http://127.0.0.1:8765
uv run python -m floodvalue.media worker        # сбор по расписанию; Ctrl+C / SIGTERM — остановка
uv run python -m floodvalue.media purge         # удалить обращения с истёкшим сроком хранения
uv run python -m floodvalue.media demo --remove # убрать ДЕМО-данные
```

`serve` и `worker` — отдельные процессы. Сбор никогда не идёт в браузере. Параллельно два
цикла не выполняются: ручной запуск во время цикла worker получит «сбор уже идёт».

- **Форма очевидца:** `http://127.0.0.1:8765/report`. Статус обращения —
  `/report/status#<токен>`; ссылку выдаёт страница после отправки.
- **Аналитик:** `http://127.0.0.1:8765/media/analyst`.
- **GeoJSON для будущего слоя «Сообщения» на глобусе:** `GET /api/media/events` (фильтры
  `origin`, `report_type`, `review_state`, `since`, `until`, `include_historical`,
  `include_demo`). События без места приходят с `geometry: null`, их нужно показывать
  списком, не на карте. Карточка — `GET /api/media/events/{id}`.

## Доступ аналитика

- `FLOODVALUE_MEDIA_ANALYST_TOKEN` не задан → операторские действия доступны **только с
  этой машины** (loopback, без `X-Forwarded-For`).
- Токен задан → вход на `/media/analyst` формой (cookie `HttpOnly`, `SameSite=Strict`, 12 ч)
  или заголовок `Authorization: Bearer <токен>`. Изменяющие запросы требуют ещё и
  заголовок `X-FloodValue-Media: 1`.
- `serve --host 0.0.0.0` без токена запускаться отказывается.
- Скрытая ссылка авторизацией не считается. Административных ключей во frontend нет.

## Тесты

```bash

```

Тесты работают без сети: сохранённые живые ответы GDACS и Copernicus
(`tests/media/fixtures/`) и синтетические публикации для новостей. Живая проверка источников — отдельная, её вывод записан в
`docs/verification/media-smoke-2026-09-26.md`.

## Безопасность, реализованная в коде

- Приём обращений: серверная валидация (pydantic, координаты, время с часовым поясом, не в
  будущем и не старше 30 дней), лимит частоты по адресу, лимит размера запроса,
  ключ идемпотентности (`idempotency_key`, один на черновик) против дублей.
- Фото: не больше 3 и 8 МБ каждое, стороны 64–8000 px, формат определяется по содержимому
  (JPEG/PNG/WebP), перекодирование в JPEG без EXIF и геотегов, случайные имена. Отдаются
  только аналитику, с `Content-Security-Policy: sandbox` и `nosniff`.
- Статус обращения — только по непрогнозируемому токену (HMAC), номер обращения доступа не
  даёт. Токен передаётся во фрагменте URL и не попадает в журналы и Referer.
- Страницы с CSP (`script-src 'self'` + jsdelivr с SRI), без inline-скриптов. Весь
  пользовательский текст выводится через `textContent`.
- Загрузчик источников: только https и хосты из `allowed_hosts`, отказ для внутренних и
  служебных адресов, проверка каждого перенаправления, таймауты, ограниченные повторы с
  нарастающей паузой, минимальный интервал между запросами к хосту, бюджет запросов.
  Остаётся риск DNS-rebinding между проверкой и соединением: для MVP с фиксированным
  списком хостов он принят.
- Текст статьи — недоверенные данные: правила ничего не исполняют, у модели извлечения нет
  инструментов, ответ модели проходит строгую схему без полей координат.

## Ограничения (честно)

- Новостной источник живьём не проверен: GDELT 26.09 отвечал 429 или не отвечал за 10 с.
  Новостной путь проверен только тестами на синтетических публикациях и ДЕМО-replay.
- Извлечение по правилам — только по заголовку (GDELT хранит только заголовок). Правила
  знают русский и английский. Возможны ложные срабатывания («затопить печь») и пропуски.
  Время события правила не извлекают: для новостей оно «неизвестно».
- Без геокодера у новостей нет координат: они попадают в список «нужно уточнить место».
- Модерация одним аналитиком, без ролей и журнала входов.
- Нет уведомлений и подписок. Нет кластеризации маркеров. Слой на глобусе не подключён.
- Подготовка и анализ новых сцен Sentinel-1 не реализованы. Для сегодняшних сообщений
  локальный каталог даёт «слишком рано», и это правильный ответ, а не сбой.
- Проверка с телефона — эмуляция мобильного Chromium (390×844, touch), не реальное
  устройство.

## Что нужно для публичного запуска (решает человек, не агент)

1. Правовое основание и порядок обработки данных: координаты, фото, IP для лимита частоты
   (хранится только хеш с солью), срок хранения. Юридической оценки здесь нет.
2. Размещение за HTTPS с обратным прокси. При прокси — корректная передача адреса клиента
   для лимитов: сейчас `X-Forwarded-For` не доверяется и выключает loopback-доступ.
3. Токен аналитика, в идеале — нормальная учётная система с ролями.
4. Антиспам сильнее лимита по адресу (капча или подтверждение).
5. Регламент модерации и удаления обращений.
6. Только после этого — `FLOODVALUE_MEDIA_PUBLIC_REPORTS=1`.
