## Протокол и границы вывода

Разбиение — `splits/split_v1.json` по событиям (D-016). Варианты U-Net и выбор чекпойнта сравнивались на dev: событие USA, 69 чипов. Validation — события Nigeria и Sri-Lanka, 60 чипов — использовалась отдельно для выбора калибратора и порога, а также для справочной проверки сглаживания по D-029. Варианты модели по validation не выбирались. Все описанные методы используют только Sentinel-1 (VV/VH и производные признаки); дополнительных данных нет, поэтому сравнение S1-only с расширенным набором признаков неприменимо. Test остаётся запечатанным по D-010; этот документ не содержит test-оценки.

Для метрик сегментации валидны пиксели с конечными VV и VH и меткой LabelHand 0 или 1. U-Net, пиксельный метод и baseline на dev используют одну маску: 17 638 830 пикселей, `valid_mask_sha256=cf89ac0b49f7819ea5581c1a8e19aed53fe9f4451a11d1472361f62e5a465bbc`. Порог в сравнении сырых вероятностей — `p ≥ 0,5`.

Dev — часть выбора: на нём выбирались вариант и эпоха U-Net, а также пиксельная модель. Поэтому результаты dev описывают этот процесс выбора и не являются независимой оценкой переноса. Для экспериментов U-Net чекпойнт каждого запуска выбирался по максимальному dev IoU при `p ≥ 0,5`. Среднее и стандартное отклонение ниже рассчитаны по трём значениям `dev_iou` из `unet-variants.csv`; SD — выборочное стандартное отклонение между seed, не доверительный интервал.

## Варианты U-Net: выбор на dev

Менялась одна ось относительно базовой конфигурации: входной признак, сдвиг каналов в dB, Dice-компонент потерь или ширина сети. Остальные параметры и протокол запусков оставались одинаковыми; у каждой строки три seed (20260925, 1, 2).

| Вариант | Единственное изменение | IoU dev по seed | Среднее ± SD | Δ к базе |
|---|---|---:|---:|---:|
| База | VV, VH, VV−VH; ширина 16; BCE + 0,5·Dice; сдвиг ±1 dB | 0,5712; 0,5555; 0,5830 | 0,5699 ± 0,0138 | — |
| Без VV−VH | Убрана разность VV−VH | 0,5539; 0,5575; 0,5857 | 0,5657 ± 0,0174 | −0,0042 |
| Без dB-сдвига | Сдвиг каналов установлен в 0 | 0,5668; 0,5718; 0,5705 | 0,5697 ± 0,0026 | −0,0002 |
| Только BCE | Вес Dice установлен в 0 | 0,5474; 0,5626; 0,5596 | 0,5565 ± 0,0081 | −0,0134 |
| Ширина 32 | Базовая ширина увеличена с 16 до 32 | 0,5494; 0,5519; 0,5487 | 0,5500 ± 0,0017 | −0,0199 |

Результат для VV−VH и dB-сдвига: влияние на dev не обнаружено — различия малые относительно разброса между seed, и оснований приписывать этим компонентам выигрыш нет. Для Dice оценка также ограничена тремя seed и одним событием: средний IoU ниже на 0,0134, примерно на величину одного SD базовой конфигурации; это не даёт надёжного вывода о переносимом эффекте Dice.

Ширина 32 уверенно отвергнута в рамках этой dev-абляции: средний dev IoU ниже базового на 0,0199, и база выигрывает во всех трёх парных запусках по seed (разности база − ширина 32: +0,0218, +0,0036, +0,0343). У вариантов ширины 32 в среднем 7,8 млн параметров против 1,94 млн у базы; среднее время обучения в имеющихся трёх запусках — 132,7 с против 74,7 с (1,78×). Таким образом, в этих запусках увеличение сети не дало выигрыша и увеличило стоимость. Это вывод для испытанной конфигурации и dev USA, а не утверждение о всех событиях или размерах сети.

Правило выбора в исходном отчёте: заменять базу, только если вариант выигрывает на dev более чем на один SD. Ни один вариант этого не показал, поэтому база сохранена. Из-за трёх seed и единственного dev-события результаты остальных абляций следует читать как «влияние не обнаружено», а не как доказательство отсутствия эффекта.

## Validation по D-029: калибратор вне события

Выбор вида калибратора делался по log-loss вне события: калибратор подгонялся на одном событии validation и оценивался на другом, затем направления менялись. Правило выбора — минимум среднего log-loss на этих двух проверках. Ниже точные значения log-loss для каждого направления и среднее из `cross_event.csv`/`calibration-val.md`.

| Калибратор | Nigeria → Sri-Lanka | Sri-Lanka → Nigeria | Средний log-loss |
|---|---:|---:|---:|
| Без калибровки | 0,1601 | 0,1920 | 0,1761 |
| Temperature scaling | 0,1615 | 0,1943 | 0,1779 |
| Platt | 0,1470 | 0,1656 | **0,1563 — выбран** |
| Изотоническая | 0,1547 | 0,1662 | 0,1604 |

Platt победил по заявленному правилу качества вероятностей, а не по IoU маски: средний IoU переноса с выбранным порогом был 0,683 у Platt против 0,685 без калибровки. После выбора тип Platt переобучили на всей validation: `p = sigmoid(1,4647·logit(p_raw) + 1,5210)`, порог маски — 0,37. Итоговые метрики на всей validation и выбор порога получены на тех же пикселях, поэтому они оптимистичны и не служат независимой оценкой. На dev при переходе от сырого `p ≥ 0,5` к Platt и порогу `p ≥ 0,37` IoU падает с 0,584 до 0,467. Platt монотонен, и порог 0,37 соответствует сырому `p ≥ 0,1975`, поэтому изменение маски объясняется рабочей точкой, а не изменением ранжирования калибратором. Это ограничение переноса выбранного порога на USA с долей воды 4,6 %.

## Validation по D-029: среднее 3×3

После калибровки сравнили исходную вероятность со средним 3×3 по калиброванной `p` (NaN не участвуют), сохранив порог 0,37.

| Часть | Без сглаживания | Среднее 3×3 | Изменение |
|---|---:|---:|---:|
| Validation ALL | 0,685 | 0,686 | до +0,0015 |
| Nigeria | 0,778 | 0,779 | +0,001 |
| Sri-Lanka | 0,621 | 0,621 | округлённая разница 0 |

Максимальный выигрыш 0,0015 IoU оценён в исходном отчёте как уровень шума. Постобработку не приняли: она меняет вероятности отдельных объектов ради практически нулевого выигрыша сегментации. Это validation-эксперимент на двух событиях, не результат на test.
