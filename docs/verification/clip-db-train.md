# Границы клиппинга dB U-Net (`CLIP_DB`) против статистик только train (issue #125, D-045)

**Зачем.** `CLIP_DB` основного метода (`src/floodvalue/model/unet/features.py:11`) —
фиксированные границы VV [−40; 10], VH [−45; 0], VV−VH [−5; 25] dB. Их записали вручную
в `acfa559` (25.09 18:51). К этому моменту на разведке уже были видны значения S1
test-чипов. `df75654` (17:32): «VV до +25.65 dB у Spain_7370579» (`docs/data.md` §4, §8
п. 1). Этот чип потом попал в test и стал демо-чипом. `203d82a` (18:13): первая версия
QC `make data` читала пиксели S1 всех 446 чипов и дала диапазон VV −89,8…+36,8, VH
−103,9…+17,4 (`docs/data.md` §11). Комментарий к `CLIP_DB` «VV reaches +25 dB on strong
scatterers (docs/data.md)» ссылается как раз на значение test-чипа `Spain_7370579`.
Чтение пикселей S1 test в QC убрано решением D-031 (`e05a78a`/`efcbe67`, 25.09
19:34–19:56). Текущий `make data` эти числа не воспроизводит. Ниже проверено, что
границы дают на одном train. Код, конфиги и веса заморожены к `eval-test`, поэтому
константы **не менялись**.

## Команда

```bash
FLOODVALUE_DATA_DIR=<путь к data> uv run --frozen python scripts/clip_db_train.py
```

Скрипт читает только `floodvalue.data.split.chip_ids("train")` (split v1, D-016) через
`floodvalue.data.io.load_s1`: dB берутся как в файле, без повторного логарифмирования.
Пиксель учитывается, если VV и VH оба конечны (NaN исключаются), метки не читаются.
Test-чипы не открываются: `chip_ids("test")` без `allow_test` вызывает `SealedTestError`.
Перцентили точные (`np.percentile` по всем валидным пикселям, без прореживания).
VV−VH — разность исходных dB до клиппинга. Commit `8a7ee46`, 26.09, около 28 с на CPU.

## Сравнение с `CLIP_DB`

| Канал | `CLIP_DB` | train p0,1 / p99,9 | Покрывает p0,1–p99,9? | Покрывает p1–p99? | Обрезано пикселей train (ниже / выше) |
|---|---|---|---|---|---|
| VV | [−40; 10] | −28,57 / 2,78 | да | да | 0,003 % / 0,005 % |
| VH | [−45; 0] | −46,07 / −4,88 | **нет, снизу** (−46,07 < −45) | да | **0,117 %** / 0,007 % |
| VV−VH | [−5; 25] | −3,14 / 26,01 | **нет, сверху** (26,01 > 25) | да | 0,034 % / **0,128 %** |

Границы, выведенные только по train тем же правилом, что у пиксельной модели
(перцентили 0,01/99,99), против `CLIP_DB`:

| Канал | train p0,01 / p99,99 | `CLIP_DB` | Разница нижней / верхней, dB |
|---|---|---|---|
| VV | −34,88 / 7,60 | −40 / 10 | CLIP_DB шире на 5,12 / 2,40 |
| VH | −48,02 / −0,82 | −45 / 0 | CLIP_DB уже снизу на 3,02, шире сверху на 0,82 |
| VV−VH | −8,02 / 32,32 | −5 / 25 | CLIP_DB уже на 3,02 / 7,32 |

Выводы:

1. **`CLIP_DB` — ручные округлённые границы, а не перцентили.** Перцентили 0,1/99,9 train
   они покрывают только у VV. У VH нижняя граница и у VV−VH верхняя лежат внутри
   хвостов train. Все границы шире p1–p99 train, а обрезается не больше 0,13 %
   валидных пикселей train на канал с каждой стороны. Это доля, которую обрезает
   выбранный клиппинг. Мерой влияния test она не служит.
2. **Клиппинг обоснован одним train.** VV max +24,67, VH min −87,5, VH max +17,4 dB.
   Экстремумы test (VV +36,8, VH −103,9) лежат далеко за границами, ни одна граница из
   них не выводится. Но мотив клиппинга в комментарии к `CLIP_DB` взят из test-чипа
   `Spain_7370579` (+25,65 dB).
3. **Влияние разведки test на выбор границ не исключено и не измерено.** Метрику при
   границах, выведенных только по train, не считали: для этого нужно переобучить
   U-Net, а код и веса заморожены к `eval-test`. Раскрыто как ограничение
   (`docs/limitations.md` §1, D-045).
4. **Остальные входные параметры получены по train:** mean/std нормализации U-Net
   (`channel_stats` по train, `src/floodvalue/model/unet/train.py:201`,
   `models/unet/config.json`) и границы клиппинга пиксельной модели (перцентили
   0,01/99,99 валидных пикселей train, каждый 25-й пиксель: VV [−35,17; 7,37],
   VH [−48,2; −1,03], `models/pixel/config.json`). Калибровка и порог подобраны на
   validation (D-029).
