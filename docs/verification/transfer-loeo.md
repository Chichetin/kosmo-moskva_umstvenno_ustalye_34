# Перенос рецепта U-Net на невиданное событие: leave-one-event-out (#86)

**Статус: ожидает прогона в Colab (D-036).** Чисел здесь нет, пока нет вывода команды: пустая
таблица лучше выдуманной. Код, тесты проводки и ноутбук-обёртка влиты; результат добавляется
отдельным PR только с документами (CSV/JSON фолдов + таблица ниже).

Критерии 7 (перенос) и 8 (контролируемый эксперимент). Что проверяется: переносится ли
**рецепт** основного метода (архитектура и обучение D-019) на событие, которого не было в
обучении, и насколько он лучше порогового baseline при одинаковой дисциплине. Итоговые веса
`models/unet/` этим отчётом **не проверяются и не меняются**. Их перенос на новые события
проверяют validation (`eval-validation.md` §7) и test (`eval-test`, #32).

## Команда

Colab (GPU), ноутбук `notebooks/loeo_colab.ipynb`, `MODE = "full"`. Ноутбук вызывает только

```bash
python -m floodvalue data
python -m floodvalue.model.unet.loeo --out-dir <OUT>/loeo        # 6 фолдов × 60 эпох, один seed
python -m floodvalue.model.unet.loeo --table-from <OUT>/loeo     # таблица этого отчёта
```

Выход: `loeo-metrics.csv` (событие × метод: IoU, F1, precision, recall, TP/FP/FN/TN,
`valid_mask_sha256`, бутстрэп-CI IoU по чипам, парная разность IoU с baseline фолда и её CI),
`loeo-chips.csv` (счётчики по чипам — для разбора ошибок), `loeo-summary.json` (конфигурация,
нормализация и порог baseline каждого фолда, AP и oracle-IoU, время, устройство, версии,
команда), `loeo.log`, `COMMIT`. Проверка проводки без GPU (числа — не результат):
`MODE = "smoke"` → `--events USA --max-chips 4 --epochs 2 --eval-epochs 1,2`.

Ограничения протокола, которые пишутся рядом с числами:

- Гиперпараметры D-019 и канал VH выбирались по dev (USA). Поэтому фолд USA не полностью
  независим для обоих методов и помечен звёздочкой.
- Один seed: разброс между seed в LOEO не измерен. Ориентир — 5 членов D-019 на dev:
  лучшая эпоха 0,555–0,583.
- На малых событиях (Somalia — 26 чипов, Pakistan — 28) и на чипах с малой долей воды CI
  широкие. 5 чипов Ghana, у которых вся метка −1, исключены ещё в split (D-016). Pooled IoU при малой доле воды неустойчив.
- `LabelHand` — вся вода, а не временное затопление. Это «карта воды».

## Разбор ошибок

*Ожидает прогона.* План разбора по `loeo-chips.csv`:

- для каждого события — FP против FN и какие чипы дают больше половины ошибок;
- зависимость IoU от доли воды и доли невалидных пикселей в чипе (те же группы, что в
  `eval-validation.md` §7);
- AP против IoU@0,5. Если AP высокий, а IoU низкий, то ранжирование переносится, но сдвинута
  шкала p (калибровка). Oracle-порог в `loeo-summary.json` смотрит на метки отложенного события:
  это только диагностика, ни для какого выбора он не используется;
- условия, при которых качество падает: влажная почва и растительность (FN), радарная тень и
  гладкие поверхности (FP), невалидные полосы S1.

## Что это даёт критериям

- **7:** распределение качества рецепта на 6 невиданных событиях в режиме только S1: U-Net
  не использует ни Sentinel-2, ни JRC, ни DEM. Дополняет, а не заменяет проверку итоговых
  весов на validation и test.
- **8:** контролируемое сравнение «U-Net против порога VH при одинаковой дисциплине» (фолд,
  нормализация и порог — только по обучающим событиям) на тех же пикселях. Выбор признаков и
  параметров U-Net объясняет `unet-metrics.md` (варианты на dev), а не этот отчёт.
