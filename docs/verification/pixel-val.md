Сгенерировано `python -m floodvalue.model.pixel.train` (commit `56288a48c682-dirty (обучено из незакоммиченного кода; код — коммит 876bc64)`, 2026-09-25). Числа — из `docs/verification/pixel-metrics.csv`. Test не читался (D-010).

## Метод

- Вход — только S1 (VV, VH в dB, как в файле). Клиппинг по train: VV [-35.17; 7.37] dB, VH [-48.2; -1.03] dB — перцентили 0.01 / 99.99 валидных пикселей train.
- Признаки (11): `VV`, `VH`, `VV-VH`, `VV_mean3`, `VV_std3`, `VH_mean3`, `VH_std3`, `VV_mean7`, `VV_std7`, `VH_mean7`, `VH_std7`. Локальные среднее и σ — окна с учётом NaN (сумма и число конечных соседей).
- Модель — `HistGradientBoostingClassifier` (scikit-learn), log-loss, вес воды 1.0, листьев 31, итераций 300, шаг 0.1, min_samples_leaf 100, без early stopping, seed 20260925.
- Обучение — только train: до 8000 случайных валидных пикселей с каждого чипа (236 чипов, 1881892 пикселей, доля воды 9.0 %); пропущены без валидных пикселей: Paraguay_34417.
- Выбор набора окон текстуры, размера деревьев и веса воды — pooled IoU на **dev** (USA), таблица ниже; вклад каждого входа — контролируемый эксперимент на dev (`docs/verification/pixel-ablation.md`). Validation — только отчёт.
- p = `predict_proba` классификатора; маска ⇔ p ≥ 0.5 (фиксировано, не подобрано на validation; порог и калибровку основного метода задаёт этап калибровки на validation по D-012).
- Валидный пиксель — VV и VH конечны и LabelHand ≠ −1; хеш маски (`model.metrics.mask_sha256`, чипы в порядке `chip_id`) совпадает с baseline: **да, все строки dev/validation**.

## Выводы

- **dev (выбор):** A лучше baseline — IoU 0.391 → 0.530, ложных срабатываний 681880 → 194421, пропусков 223697 → 275163; парный ΔIoU +0.139 [+0.061; +0.205].
- **validation (подтверждение) при p ≥ 0.5:** A хуже baseline — IoU 0.580 → 0.445, ΔIoU -0.135 [-0.260; -0.021]. Precision 0.838 → 0.968, Recall 0.653 → 0.452: A почти не даёт ложных тревог, но пропускает воду.
  - Nigeria: IoU 0.572 → 0.598, Recall 0.597 → 0.609.
  - Sri-Lanka: IoU 0.585 → 0.321, Recall 0.698 → 0.325.
- Порог 0,5 не переносится между событиями: на validation при t = 0.20 IoU A = 0.636, а на dev тот же t даёт 0.366 (кривая ниже). 0.636 — оракульная верхняя оценка (t подобран на той же validation), для выбора не используется и несопоставима с методами при их фиксированном пороге. Калибровку A пришлось бы и подбирать, и проверять на одной validation (D-012), честной оценкой осталась бы только test.
- Описательная статистика воды (медиана VV / VH, dB, пиксели метки 1; не используется для настройки): train -15.7 / -24.0; dev -18.7 / -26.6; validation:Nigeria -18.0 / -25.0; validation:Sri-Lanka -12.6 / -24.9. Гипотеза для Sri-Lanka: VH воды там такой же тёмный, как в train, а VV заметно ярче, и классификатор, опирающийся на VV и текстуру, отвергает такую воду; пороговое правило по одному VH этого не видит.
- Выбор на dev смещён вверх: 0,530 — максимум из 18 точек сетки на том же dev, поэтому ΔIoU к baseline на dev завышен («проклятие победителя»); веса воды 2 и 4 отвергнуты при фиксированном p ≥ 0,5, т. е. вместе с рабочей точкой — вопрос веса и порога не закрыт.
- Ограничение: dev — одно событие; вес воды 1 выбран на dev с малой долей воды (4,6 %); вероятно, это и занижает p на событиях с большей долей воды. Гипотеза про VV на Sri-Lanka проверена только описательной статистикой выше, без отдельного эксперимента.
