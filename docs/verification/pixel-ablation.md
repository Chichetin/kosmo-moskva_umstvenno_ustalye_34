## Выводы

- Один канал: VH (0.441) лучше VV (0.390), ΔIoU +0.051 — как у baseline (D-021).
- Оба канала: VV+VH 0.478 против VH 0.441 (ΔIoU +0.036); явное отношение VV−VH к паре каналов почти ничего не добавляет (+0.001) — деревья и так видят оба канала.
- Текстура (локальные среднее и σ) добавляет сверх пары каналов: окно 3 — +0.028, окна 3/7 — +0.051 IoU (0.479 → 0.530).
- На dev (событие, не участвовавшее в обучении) крупные окна снижают IoU: 3/7 — 0.530, 3/7/15 — 0.510, 3/7/15/31 — 0.481. С ростом окна падает Precision (0.731 → 0.637) при почти той же Recall. Гипотеза (не проверялась отдельно): широкое окно переносит воду на сухие пиксели у берега.
- Лучший вариант на dev — **+текстура 3/7** (IoU 0.530, 95 % [0.409; 0.635]); baseline на тех же пикселях — 0.391. Итоговая конфигурация — «+текстура 3/7»; ближайший соперник «+текстура 3/7/15»: ΔIoU +0.020 [+0.012; +0.030] в пользу итоговой, значимо.
- Ограничение: dev — одно событие (USA, 69 чипов, 4,6 % воды), поэтому интервалы широкие, а выбор опирается на парные интервалы, а не на точечные значения. Набор окон выбирался на том же dev вместе с гиперпараметрами (`pixel-val.md`), поэтому превосходство итогового варианта на dev частично задано отбором; независимое подтверждение — validation (`pixel-val.md`) и test после заморозки. Validation для выбора входов не использовалась.
