# КосмоХакатон 2026 — кейс FloodValue

**ИИ-оценка экономического ущерба от паводка и оптимизация заказа ДЗЗ**
«От карты паводка к обоснованному заказу ДЗЗ»

Первоисточник: `FloodValue_Постановка_КосмоХакатон.pdf` (23 с.) и `FloodValue_Критерии_КосмоХакатон.pdf` (4 с.), полный текст — в `FloodValue_Постановка.txt` и `FloodValue_Критерии.txt`. Этот файл — структурированная выжимка, при расхождениях приоритет у PDF.

## 1. Суть задачи

Разработать **воспроизводимую систему**, которая по официальным данным **Sentinel-1** (из Sen1Floods11) двумя обязательными методами определяет воду:

1. **пороговый baseline** (бинарная маска);
2. **самостоятельный основной метод** (вероятности + согласованная бинарная маска + оценка неопределённости).

По вероятностям основного метода:

- оценить **прямой ожидаемый ущерб (EL)** десяти условных объектов и его неопределённость;
- сформировать **зоны дополнительной съёмки** (собственные полигоны ≥ 1 км²);
- сравнить **стратегии A/B/C** при объявленном командой бюджете;
- показать всё в **интерфейсе оператора**.

Изменение бюджета пересчитывает план **без повторного обучения модели**.

Дополнительные открытые бесплатные данные (OSM, рельеф, S2, земной покров, предобученные модели) допустимы при раскрытии источника, версии/даты, лицензии и доступности на момент моделируемого решения. Запрещено использовать информацию, возникшую **после даты анализируемого события**. Решение обязано работать в режиме **S1-only**.

Целевые статьи по теме: https://disk.360.yandex.ru/d/xehr4MEGjTQ4pg

## 2. Данные

**Единственный обязательный источник** — официальный Sen1Floods11: https://github.com/cloudtostreet/Sen1Floods11 (бакет `gs://sen1floods11`, v1.1). Организатор ничего не переупаковывает и не выдаёт.

| Слой | Содержание |
|---|---|
| S1 | GeoTIFF 512×512, 2 канала VV/VH, Float32, **dB** (не логарифмировать повторно) |
| QC / LabelHand | 1 канал Int16: −1 — нет надёжной метки, 0 — не вода, 1 — вода |
| S2 | 13 каналов L1C, UInt16, без QA-маски облаков |
| JRCWaterHand | постоянная вода JRC (может использоваться для отделения постоянной воды) |

Имя файла: `EVENT_CHIPID_LAYER.tif`. Все чипы в EPSG:4326, номинально 10 м. Площадь типового чипа ≈ 26,2144 км².

Метка «1 — вода» **не** отделяет временное затопление от постоянной воды. Без обоснованного отделения (временно корректным источником) результат называть **«карта воды»**, а не «карта временного затопления».

**Нельзя выкладывать Sen1Floods11 в GitVerse** — описать получение из официального источника.

Организатор **не предоставляет**: train/val/test, синтетику, портфели, координаты объектов, пример решения, кандидатные зоны, прайс-лист, скрытую выборку, эталонные предсказания, обученные модели.

## 4. Методы и протокол проверки

- Независимое разделение S1-данных **без утечки** (по событиям/сценам; можно использовать авторский split с указанием версии). Списки чипов, seed и код разбиения сохраняются.
- Baseline и основной метод сравниваются **на одних валидных тестовых пикселях**: IoU, F1/Dice, Precision, Recall, число пикселей; различия по событиям, ложные срабатывания, пропуски.
- Простая замена порога baseline **не** считается новым методом.
- Порог бинаризации, checkpoint, калибровка выбираются **только на validation**. Test не трогать для подбора.
- Минимум **один контролируемый эксперимент** (абляция), обосновывающий конфигурацию основного метода. При использовании доп. данных — сравнить S1-only с расширенным вариантом.
- Статистики нормализации — только по train.
- Показать **надёжность вероятностей** (калибровка на независимой проверке) и **показатель неопределённости**, проверенный на связь с ошибками.
- Модель должна запускаться на **другом официальном S1-чипе** без подгонки (жюри может выбрать свой чип).

## 5. Экономическая модель

Для точечного объекта i:

```
EL_i = p_i × V_i × q_i
```

- p — вероятность воды из `flood_probability.tif` в координате объекта, **независимо от бинарной маски** (EL не обнуляется, если p ниже порога);
- V, q — из таблицы типов.
- Объект в nodata → `status = partial/no_data`, p/EL/rank пустые (не ноль).
- Контрольный расчёт: p = 0,4; V = 10 млн; q = 0,25 → EL = 1 млн руб.

**Прокси-проверка ущерба**: на независимой проверочной выборке с валидными метками y∈{0,1} сравнить EL = p·V·q с EL_ref = y·V·q; указать правило выбора контрольных точек, их число и метрику ошибки. Если на демо-чипе нет меток — проверка на отдельном размеченном тестовом чипе.

**Чувствительность** (обязательно): EL к p, V, q по отдельности; план закупки — к бюджету и хотя бы одному экономическому параметру (например, ставке).

Не умножать рублёвый ущерб на «коэффициент важности» — социальный приоритет вводится как отдельное явное ограничение.

## 6. Стратегии A/B/C

Одна карта вероятностей, один чип, один портфель, один момент решения, одна функция цены.

| Стратегия | Смысл |
|---|---|
| A — открытые данные | Нет платных заказов; остаются затраты обработки и проверки |
| B — широкая закупка | Широкое покрытие по заранее объявленному правилу; при превышении бюджета помечается как **контрфактическая** |
| C — выборочная закупка | Подмножество каталога по EL, неопределённости, цене и ограничениям; **соблюдает бюджет** |

Полная стоимость: `C_decision = C_data + C_compute + C_review + C_field + C_action_errors` (последний член — только при наличии модели действия).

- `covered_expected_loss_rub` — сумма EL **уникальных** объектов, покрытых пригодными и доступными к сроку зонами; повторное покрытие не умножает EL.
- `coverage_share` = covered / суммарный оценённый EL.
- Архивный снимок — контекст, а не наблюдение текущей воды.
- Без новых наблюдений снижение неопределённости — только `scenario`, не `measured`.

## 7. Зоны заказа (кандидатные полигоны)

- Команда сама создаёт `candidate_orders.geojson`: валидные Polygon WGS84 (порядок **[долгота, широта]**), **без holes и самопересечений**, площадь **≥ 1 км² до округления**.
- Площадь — по контуру, в **EPSG:6933** (м² / 1 000 000), запись с точностью 0,001 км², ROUND_HALF_UP. 0,9996 км² — недопустимо.
- Покрытие точек: `polygon.covers(point)` (включая границу), объединение по уникальным asset_id.
- Каждый полигон — отдельная оплачиваемая позиция, пересечения не уменьшают цену.
- Один каталог для B и C.
- Обязательные самопроверки: валидность Polygon, отсутствие holes, площадь ≥ 1 км², совпадение записанной и вычисленной площади, уникальность candidate_id/asset_id, отсутствие двойного учёта, воспроизводимость стоимости.

## 8. Тариф (учебный сценарий по ПП РФ № 840, ред. 27.08.2025, контрольная дата 20.09.2026)

```
РП = Б × К × О × П × Т × Р
```

| Символ | Смысл | Поле |
|---|---|---|
| Б | ставка за 1 км², **сценарная 788,64 руб.** (`base_rate_status=scenario`) | `base_rate_rub_km2` |
| К | площадь, км² (1 БРЕ = 1 км²) | `area_km2` |
| О | уровень обработки: L0 = 1, L1 = 1, L2 = 1,2 | `processing_coef` |
| П | использование: internal = 1, limited = 1,2, unrestricted = 1,5 | `usage_coef` |
| Т | актуальность: new + guaranteed_purchase = 1,8; operational (≤ 90 дн.) = 1; archive (> 90 дн.) = 0,6 | `freshness_coef` |
| Р | скидка за объём (см. ниже) | `discount_coef` |

Скидка (S — площадь группы в км², r — разрешение в м, ln — натуральный):

```
оптика: P_opt = min(1, max(0.2, −0.058·ln(S/r²) + 1.037))
радар:  P_sar = min(1, max(0.7, −0.020·ln(S/r²) + 1.031))
```

Правила учебного расчёта:
1. Частный коммерческий пользователь (не орган власти).
2. Группировка позиций по типу данных, разрешению и календарному году → `discount_group_id`; S и Р пересчитываются для всей корзины при любом изменении набора (нельзя суммировать заранее посчитанные цены одиночных зон).
3. Округление: скидка — 9 знаков, цена за км² и цена позиции — до копеек, ROUND_HALF_UP; итог — сумма позиций.
4. НДС, доставка и т.п. — не добавлять автоматически.

Контрольная арифметика (Б = 788,64; 1 км²; оптика 1 м; L2; internal): новая гарантированная — **1 703,46 руб.**; operational — **946,37 руб.**; archive — **567,82 руб.**

Нормативные источники: ПП РФ № 840 от 29.06.2019; ПП РФ № 1297 от 27.08.2025; Приказ ГК «Роскосмос» № 116 от 21.05.2026 (методика БРЕ). Указать редакцию и дату собственной проверки.
