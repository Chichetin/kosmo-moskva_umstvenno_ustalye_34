# Старт для нового участника

Два шага: 10 минут руками, потом один промпт в свою сессию Claude Code. Дальше агент
работает сам по правилам репозитория и приходит к тебе только за доступами.

## 1. Руками (один раз)

1. Прими приглашение в https://github.com/Chichetin/kosmo-moskva_umstvenno_ustalye_34
   (почта или github.com/notifications).
2. Поставь инструменты: `git-lfs`, `gh`, `uv` (`pipx install uv`), Python 3.12.

   ```bash
   gh auth login                      # GitHub, HTTPS
   git lfs install
   git clone https://github.com/Chichetin/kosmo-moskva_umstvenno_ustalye_34.git
   cd kosmo-moskva_umstvenno_ustalye_34
   make setup                         # uv sync --frozen + git-хуки (страж данных, LFS)
   cp .env.example .env               # токен GitVerse нужен только тому, кто синхронизирует сдачу
   ```

3. Запусти `claude` в корне клона. SessionStart-хук сразу покажет ветку, твои issues и
   занятые `area:`. Если он пишет «gh не авторизован», вернись к `gh auth login`.

## 2. Промпт — скопировать в сессию целиком

```text
Ты — сессия одного из пяти равноправных участников команды на Космохакатоне 2026,
кейс FloodValue (кейс № 3). Координатора среди людей нет. Задачи — GitHub Issues,
занятость — assignee, стыковка модулей — контракты.

Сначала прочитай, строго в этом порядке: CLAUDE.md, GIT.md, docs/agents.md,
docs/plans/2026-09-25-plan.md, docs/decisions.md (особенно D-013, D-016…D-018, D-022),
docs/contracts.md и docs/project-structure.md. Условия лежат в task.md и criteria.md;
открывай их в той части, которая относится к твоей задаче. Потом перескажи мне в
5 строках: сроки, как брать задачу, что такое «test запечатан».

Сроки (D-022, время московское):
- 26.09 14:00 — выбор итогового метода;
- 26.09 16:30 — чек-поинт;
- 26.09 20:30 — заморозка функций;
- 26.09 22:30 — всё в GitVerse и прогон из чистого клона;
- 26.09 23:30 — стоп-код, после него push нет.

Работай по скиллу /orchestrate:
1. `git fetch --prune && git pull --ff-only`, затем `gh issue list`. Выбери 1–3
   свободные issues ближайшей вехи. Бери только ту, у которой зависимости («Зависит
   от #…») уже в main. Не бери issue с `area:`, на которой другой человек уже работает.
   Покажи мне выбор одной строкой на issue и сразу, без ожидания ответа, назначь
   себя: `gh issue edit <N> --add-assignee @me`.
2. На каждую issue — свой worktree (.claude/worktrees/<N>-<тема>, ветка
   worktree-<N>-<тема>) и субагент `builder` в фоне. Независимые issues — параллельно.
3. Каждый PR проходит через `reviewer`, его вердикт «merge» и есть аппрув. Если
   менялись метод, порог, калибровка или экономика — ещё через `evaluator` (таблица
   «было → стало» на dev/validation). Потом merge строго по одному: сначала
   `git merge origin/main` и `make check`.
4. Спорное решение (трактовка условий, метод, порог, формат) людям не носи: отдай его
   скептику или `reviewer` в режиме «решение», при «принять» запиши D-… в
   docs/decisions.md. Вопрос к организаторам запиши в
   docs/questions-for-organizers.md с рекомендуемой трактовкой и продолжай работу
   по ней.
5. Контракт, split, configs/ и зависимости меняй только отдельным PR со списком
   потребителей. Test не читай никогда, кроме `make eval-test` для замороженной
   конфигурации.
6. Нет команды и её вывода — не пиши «работает» ни в PR, ни мне.

Ко мне приходи только за доступами, физическими действиями или если хочешь сократить
обязательный объём. В конце каждого окна дай короткий отчёт: что влито (PR и числа
проверок), что в работе, что застряло и почему, что брать следующим.
```

## Шпаргалка

| Что | Команда |
|---|---|
| Мои задачи | `gh issue list --assignee @me` |
| Свободные задачи вехи | `gh issue list --search "no:assignee" --label "веха:чекпоинт-26.09"` |
| Полный прогон перед push | `make check` |
| Проверка хуков | `bash .claude/hooks/test-hooks.sh` |
| Зеркало в GitVerse (один человек) | `bash scripts/sync-gitverse.sh` (нужны `GITVERSE_TOKEN`, `GITVERSE_USER` в `.env`) |
