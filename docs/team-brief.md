## Почему C с 75 % до 8,7 % — это улучшение

**Что такое «покрытый ущерб».** В `strategy_comparison.csv` колонка `coverage_share` — какая доля ожидаемого
ущерба портфеля (EL = p·V·q) приходится на объекты, попавшие под купленные снимки. Это не точность и не «доля
правильных ответов». Большой процент значит лишь «снимали объекты с большим ожидаемым ущербом», а не «снимали с
пользой». В условиях об этом прямо: «Высокий ожидаемый ущерб — основание проверить зону, но не доказательство, что
любой снимок этой зоны полезен» (`task.md`, «Выбор дополнительной съемки»).

**Пример на демо-чипе** (`make all CHIP=Sri-Lanka_713926 BUDGET=5000`, файлы `asset_loss.csv`,
`procurement_plan.csv`). V·q — ущерб объекта, если вода в точке есть; EL = p·V·q — ожидаемый ущерб.

| Объект | p | V·q | EL | Вероятность ошибиться без снимка, min(p, 1−p) |
|---|---|---|---|---|
| A02 | 0,978 | 8,0 млн руб. | 7,83 млн руб. | 2,2 % |
| A10 | 0,997 | 4,8 млн руб. | 4,79 млн руб. | 0,3 % |
| A01 | 0,970 | 2,5 млн руб. | 2,43 млн руб. | 3,0 % |
| A08 | 0,375, маска неустойчива | 2,7 млн руб. | 1,01 млн руб. | **37,5 % — модель сомневается** |
| A05 | 0,080 | 4,2 млн руб. | 0,34 млн руб. | 8,0 % |
| A03 | 0,076 | 1,5 млн руб. | 0,11 млн руб. | 7,6 % |

- **Старое правило** выбирало снимки по ожидаемому ущербу на рубль и купило две зоны над A02 и A10. По карте там
  почти наверняка вода (p 0,978 и 0,997), и бригада поедет в любом случае: A02, A10 и A01 — первые в очереди
  осмотра с действием «выезд и меры сразу» (D-035, `assets_metadata.json`). Снимок почти наверняка не изменил бы
  решение. Зато у A02 и A10 большой ожидаемый ущерб, поэтому «покрыто 75 %».
- **Новое правило (D-049)** купило две зоны. E-2 (1 754,56 руб.) — над A08, где модель честно не знает ответ:
  ожидаемый ущерб 1,01 млн руб., при воде в точке — 2,7 млн. Z-A03 (2 452,98 руб.) — над A03 и A05: там шанс
  ошибиться около 8 % (у A02 — 2,2 %), а на кону 4,2 и 1,5 млн руб. У A08, A05 и A03 ожидаемый ущерб мал из-за низкой
  p, а не потому что объекты дешёвые (у A05 V·q больше, чем у A01). Поэтому «покрыто» только 8,7 %.

| | Старое правило C | Новое правило C (D-049) |
|---|---|---|
| Цена снимков (бюджет 5 000 руб.) | 4 905,96 руб. | 4 207,54 руб. |
| Покрытый ожидаемый ущерб (`coverage_share`) | 74,9 % | 8,7 % |
| **Адресуемая цена ошибки решения (сценарий, `decision_risk_share`)** | **9,2 %** | **70,6 %** |
| Остаточная неопределённость по непокрытым объектам (сценарий; без снимков, как у стратегии A, — 2,79) | 2,61 | 1,04 |

Полная стоимость решения C по новому правилу (снимки + прочие затраты) — 6 207,54 руб. (`decision_cost_rub`).

**Цена ошибки решения** R = V·q·min(p, 1−p) — сколько в среднем стоит ошибиться с решением «ехать / не ехать» без
нового снимка. Она велика, когда на кону много денег **и** модель не уверена, и почти нулевая, когда ответ по карте
известен. Снимки нового правила приходятся на объекты, где сосредоточено 71 % этой суммы, и они дешевле старых.
Это **сценарная** величина (`uncertainty_status=scenario`): снимки не куплены, фактически неопределённость не
снижена, и снижение потерь мы не заявляем (D-049). 71 % — следствие правила, которое по построению выбирает по R,
а не доказательство; довод — сама логика решения выше.

**Как это связано с условиями.** В постановке C — «набор по ожидаемому ущербу, неопределённости, цене и
ограничениям» (`task.md`, «Три стратегии»). По критерию 10 неопределённость должна влиять на ущерб либо на выбор
съёмки — в D-049 она прямой фактор выбора. Старое правило (D-038) учитывало неопределённость только при равенстве
остальных факторов. Оператор по D-001 не должен платить за снимки, которые ничего не проверяют.

**Что говорить на защите и показывать в интерфейсе:**

- показывать у C оба числа: 8,7 % ожидаемого ущерба (метрика из обязательной таблицы) и 71 % адресуемой цены
  ошибки решения; для сравнения B — 100 % за 42 465,93 руб., это сверх бюджета, то есть **контрфактическая**
  стратегия (`budget_feasible=false`);
- фраза: «Мы не покупаем снимки, которые подтверждают то, что карта и так показывает. Объекты, где по карте почти
  наверняка вода, сразу идут на осмотр, а снимок берём там, где он может изменить решение»;
- старое правило показать рядом для сравнения — оно уже посчитано: строка `C_by_EL` в `sensitivity.csv`;
- честные оговорки: R — сценарная величина, а не снижение потерь; она опирается на откалиброванную p (на dev
  калибровка хуже, см. выше), идеальный снимок и одинаковую цену ошибки в обе стороны. Если снимок нужен ещё и для
  другого (например, задокументировать масштаб ущерба), съёмка A02 тоже имеет смысл;
- числа Sri-Lanka устареют после смены демо-чипа на `Spain_7370579` (D-033) — тезисы пересчитать.

Те же числа для жюри — README, раздел «A/B/C при бюджете 5 000 руб.», и `docs/verification/procurement-catalog.md` §5.

## Словарь

- **IoU** — доля совпадения карты воды с разметкой: пересечение, делённое на объединение; 1 — идеально.
- **AP** — качество упорядочивания пикселей по вероятности воды без выбора порога; 1 — идеально.
- **ECE** — насколько вероятности честны: при p = 0,7 вода должна быть примерно в 70 % случаев; 0 — идеально.
- **AUROC** — насколько показатель неопределённости выше на ошибках, чем на верных пикселях; 0,5 — не различает, 1 — идеально.
- **seed** — начальное значение случайности при обучении; разные seed дают немного разные модели.
- **LOEO** — проверка «оставь одно событие»: учим на пяти событиях, проверяем на шестом, невиданном.
- **validation / dev / test** — части данных по событиям: dev — выбор модели, validation — калибровка и порог,
  test — единственная независимая итоговая проверка.
- **V, q, EL** — стоимость объекта, доля ущерба при затоплении, ожидаемый ущерб p·V·q.
- **R** — цена ошибки решения V·q·min(p, 1−p), сценарная величина.
