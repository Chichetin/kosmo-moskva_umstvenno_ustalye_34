# Система агентов

Пять равноправных участников, у каждого своя сессия Claude Code. Общего оркестратора
нет: каждая сессия ведёт свои issues по скиллу `orchestrate` и сама гоняет субагентов.
Определения ролей — `.claude/agents/*.md`. Правила проекта роли получают из `CLAUDE.md`,
в промпте роли — только что она видит, что может, что возвращает.

## Роли

| Роль | Модель | Когда | Видит и может | Возвращает |
|---|---|---|---|---|
| сессия участника | — | всё окно | основная копия (чтение, `pull --ff-only`); берёт issues, заводит worktree, запускает агентов | итог окна |
| `builder` | opus | одна issue | свой worktree, все инструменты; тест → код → PR → `reviewer` → merge | PR, merge-commit, проверки с числами |
| `reviewer` | opus | **каждый** PR и каждое спорное решение | только diff против `origin/main`, условия, контракты; ничего не правит | `merge` / `доработать` / `отклонить` с `файл:строка`; утечка test; потребители контракта |
| `evaluator` | sonnet | после каждого изменения метода, порога, калибровки, экономики | запускает пайплайн и валидатор; пишет только `docs/verification/`; test — только `eval-test` замороженной конфигурации | таблица «было → стало» на validation |
| `operator` | sonnet | перед вехой, после правок интерфейса | интерфейс в роли инфраструктурного оператора | что непонятно, топ-3 правки |
| `scribe` | sonnet | README, ограничения, итоги вех | свой worktree, только документы; каждое утверждение — командой | PR с документами |
| `jury` | opus | перед каждой вехой; арбитр после двух `отклонить`; репетиция защиты | только артефакты | оценка 0–5 × 20, топ-5; или 15 вопросов |

`opus` — там, где нужно суждение (метод, калибровка, неопределённость, экономика,
ревью, жюри); `sonnet` — механика (прогоны, документы, проход интерфейса). Скептик для
спорного решения — `reviewer` в режиме «решение» или свежий `general-purpose` с
контекстом только из решения и условий.

## Субагентов не экономим

- `reviewer` — на каждый PR, без исключений: его `merge` и есть аппрув.
- Параллельные `builder` — на независимые issues, каталоги не пересекаются.
- `evaluator` — после каждого изменения метода, порога, калибровки, экономики.
- `jury` — перед 25.09 21:00, 26.09 16:30, 26.09 22:00, 27.09 00:00 (стоп-код 27.09 01:00, D-033).
- Скептик — на каждое решение, которое пишется в `docs/decisions.md`.

## Цикл решения без людей

```
решение → скептик/reviewer («решение») → принять → D-… в decisions.md → работа
                                        → отклонить → исправить → повторить
                                        → отклонить ×2 → jury (арбитр)
```

К человеку — только доступы, физические действия, вопросы организаторам (не
блокируясь), сокращение обязательного объёма.

## Цикл issue

```
gh issue edit --add-assignee @me → worktree → builder (тест → код → validate → PR)
  → reviewer → [evaluator, если метод/порог/экономика] → merge origin/main + make check
  → gh pr merge --merge → уборка
```

## Хуки

| Событие | Хук | Что делает |
|---|---|---|
| SessionStart | `session-context.sh` | ветка, worktree, мои issues, занятые `area:`; без gh — предупреждение |
| PreToolUse (Bash) | `check-data-files.sh pre-tool` | `git commit` с растрами Sen1Floods11 или файлом ≥ 5 МБ вне LFS — отказ |
| Stop | `check-secrets.sh`, `check-tests.sh`, `check-upstream.sh stop` | секреты; красный pytest; чужие коммиты в моих файлах/контрактах |
| PostToolUse | `check-upstream.sh post` | то же, раз в 5 минут, без блокировки |
| SubagentStop | `check-worktrees.sh` | секреты и данные во всех worktree |
| git pre-commit | `.githooks/pre-commit` | тот же страж данных для людей (`make setup`) |

Проверка: `bash .claude/hooks/test-hooks.sh`.
