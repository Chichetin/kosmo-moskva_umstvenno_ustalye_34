# Автопилот обучения FloodValue — регламент

Полный исходный промпт — `docs/prompts/training-autopilot-prompt.md`. Здесь — как он применён
к этому репозиторию. Конфигурация и критерии выбора — `configs/training-autopilot.yaml`
(протокол v1 зафиксирован 26.09 02:25 до новых экспериментов).

## Что делает

Цикл «изменения → гипотеза → обучение → оценка → проверка отображения → решение → запись
состояния». Один виток — один безопасный шаг; долгие прогоны идут отдельными процессами.

## Протокол оценки (v1)

- **Отбор рецептов — LOEO** (`python -m floodvalue.model.unet.loeo`): 6 фолдов по событиям
  train+dev, U-Net учится на 5 событиях, оценивается на 6-м на фиксированной эпохе (без выбора
  чекпойнта). Validation и test не читаются. Главная метрика — mean6 AP (без порога):
  рабочий конвейер заново калибрует p и выбирает порог на validation (D-029), поэтому IoU при
  0,5 искажает сравнение рецептов, сдвигающих вероятности.
- **Шум seed** — `docs/verification/loeo-sweep/r0_ref` против `r1_seed1`: AP ±0,013.
- **Продвижение** — только если кандидат выше обоих эталонов на ≥ 0,02 mean6 AP на двух seed,
  без провала отдельного события > 0,08 AP; затем ансамбль 5 seed, калибровка на validation
  (`make calibrate`), `eval-test --part validation` «было → стало», PR с reviewer и evaluator.
- **Test запечатан**: автопилот его не читает; `eval-test --part test` — отдельное действие
  команды (#32) для замороженной конфигурации (D-030, D-033).

## Проверки корректности (каждый кандидат и каждое изменение predict/export)

- p конечна, в [0, 1] на валидных пикселях, nodata −9999; mask ⇔ p ≥ threshold (`make validate`).
- Сетка растров = сетка S1 (CRS EPSG:4326, transform, shape); GeoJSON [lon, lat].
- Метка −1 и NaN S1 не участвуют в обучении и метриках (`data.io.valid_mask`).
- Смена бюджета не меняет p, маску, порог, портфель (тесты procurement).
- Отображение: значение p в контрольных координатах совпадает в tif → API → карте;
  ошибка модели и ошибка отображения разделяются (промпт, п. 6).

## Git

- Основная копия репозитория не используется (там идёт чужая работа). Эксперименты — в своих
  worktree на зафиксированном commit, результаты — в ветках и PR; в main автопилот сам не вливает.

## Запуск — только явно

Автопилот личный: его запускает тот, кто ведёт обучение на своей машине, в своей сессии,
командой `/loop` **с текстом задания** (без интервала — самостоятельный темп, ~20 мин):

```text
/loop Выполни один безопасный шаг автопилота обучения FloodValue по docs/automation/training-autopilot.md (исходный промпт — docs/prompts/training-autopilot-prompt.md): прочитай HANDOFF.md и state.json в /home/m1hairu/Documents/final_cosmohack/autopilot/, проверь процессы, изменения Git, очередь и бюджеты; при необходимости обнови tracking-worktree, проверь завершившийся эксперимент, исправь обнаруженную проблему или запусти следующую попытку. Не дублируй активные задачи. Test не читать. Обнови постоянное состояние и кратко сообщи результат.
```

- **Проектного `.claude/loop.md` нет и создавать его нельзя** (п. 11 исходного промпта здесь не
  применяется): он срабатывает у каждого участника, вызвавшего `/loop` без аргументов, и
  запустил бы автопилот в чужой сессии.
- **Правило восстановления в `CLAUDE.md` не добавляется** (это требование п. 12 промпта здесь не
  применяется): `CLAUDE.md` читают сессии всей команды, а автопилот касается одного человека.
  Восстановление — только вставкой текста из `docs/automation/training-resume.md`.
- Перед запуском проверить, что расписания автопилота ещё нет: два одинаковых `/loop` не заводить.

## Планирование и восстановление

- В этой машине цикл ведёт сессия Claude Code в режиме AFK: `/loop` с текстом задания (см.
  «Запуск»), пульс `.afk/heartbeat`; внешний сторож `afk-watch` поднимает сессию после лимита
  или обрыва. Отдельный supervisor на `claude -p` не заводится: два управляющих запрещены.
- После новой сессии или сжатия контекста — человек вставляет текст из
  `docs/automation/training-resume.md`.
